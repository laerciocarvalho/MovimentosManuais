UI: Admito que o ideal seria a parte da UI ter sido gerenciada pelo Angular, mas prezando pela rapidez dentro do que tenho mais familiaridade (Angular faz parte dos meus estudos, e avançando), e para entregar o desafio em um fim de semana, preferi fazer uso do meu velho conhecido ASP.NET WebForms, para entregar rápido usando uma tecnologia que também é suportada pelo cliente.

3.1) Banco de Dados: SQL Server

3.2) Persistência: ADO.NET usando AddWithValue. Com parâmetros, o valor digitado pelo usuário é tratado como dado, e não como um pedaço do comando SQL. Mesmo que alguém tente injetar código malicioso, o banco não executa.

Clean Architecture com ASP.NET WebForms não é o casamento perfeito. WebForms tem a tendência do acoplamento forte com o Code-Behind. Mas elenquei um “diplomata” para intermediar os dois mundos: o MVP (Model-View-Presenter), que é a mesma abordagem que eu adotaria se o desafio fosse em Windows Forms. Na verdade, Model-View-Presenter já era uma boa prática desde os “anos dourados” do WebForms, antes do .NET Core e dos Controllers.
